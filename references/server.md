# R1 服务端：新建、已有与迁移

这是由 AI 执行者编排的版本适配流程，**不是随包一键部署脚本**。每步使用 [操作契约](operations.md) 和 [任务卡](checklist-template.md)。目标操作通常在 Linux 服务器执行，客户端验证在用户许可的独立测试环境执行；不要在本机误运行服务器防火墙命令。

## S0 身份、入口与系统前提

进入：R1 已选中且用户有管理权限。只有 SOCKS/HTTP 的地址、端口、账户、密码不能进入本路线，需卖家提供服务端支持或管理权限；不尝试把代理密码用于 SSH。

读取：O2、目标发行版信息、现有 SSH 配置。由用户给出的目标与当前实例详情确认身份、真实SSH端口、host key 和现有业务；记录版本/服务管理器/监听。若需要调整防火墙，先在任务卡说明保留哪条管理路径，并证实新的SSH会话仍可建立。

通过：目标身份、管理入口与操作范围确定。系统未知、权限不足或 SSH身份不符则停止，不重置密码、换端口或重装。

## S1 首次安装或保留已有安装

### 首次环境

读取已选来源的**精确版本**发布说明、安装器、全部下载来源及所需系统/架构。官方候选入口为 [MHSanaei/3x-ui](https://github.com/MHSanaei/3x-ui)，但不能仅因技能举例就替换用户选择的 fork。

必须在适配卡填：repository、tag/commit、OS/architecture、安装资产或脚本URL及校验依据、该版本确实支持的参数、将写入的路径/单位/端口、安装后验证命令。下载脚本到私有文件先读；禁止 `curl | bash`、浮动 master 安装命令或猜测 `--version`/无人值守参数。安装器若会动态下载其他来源/最新版，也须把其选择固定并核对；无法固定或审阅则停止，不能说已安全部署。

只有安装授权覆盖实际操作后，执行卡中**已核实**的确切命令一次。0 + 二进制版本/服务单位/监听回读一致才通过；任何非零或与预期不同停止，记录已创建文件/服务，不自动换安装器或回滚。无网络或无版本材料时该阶段 blocked，保留方案。

### 已有环境

不执行安装器、系统 full-upgrade 或重启。O2定位已存在的真实版本、服务单位和二进制；只修改用户要改变的对象。迁移先证实源与目标版本/模型可转换，再做S2。不能因不同schema自动升级、复制整个数据库或复制独立节点私钥。

## S2 数据与参数基线

进入：实际数据库与生成配置路径已证实。先 O1 `snapshot` 获得一致快照、权限和摘要；其他拟改文件独占备份到私有目录，路径/权限记录。备份失败停止写入。

阅读真实 schema：三表 `clients/client_inbounds/client_traffics` 与 `inbounds.settings` 内嵌模型分开。`flow_override` 只在实际字段存在时适用；不据版本号猜模型。此包**不支持通用 SQL 修改**，旧文档中的直接 UPDATE 示例已撤除；修改客户端优先使用实际版本面板/API，并核对保存模型及生成结果。

迁移参数：同一逻辑节点且用户要求保留凭据时才能复用；独立节点只对齐协议形态，UUID/密钥分别生成。实际schema中的整数列（如tg_id）不能填空字符串；通过受支持接口保存后仍须核对生成结果。记录旧对象数量、启用状态、入站关联、流量记录和对应flow的布尔一致性，不打印任何凭据。

## S3 入站与客户端（目标面板）

先读取当前版本的添加/编辑入站页面或该版本API定义，将工具调用/方法/URL/字段填入适配卡。不要假定 `x-ui setting`、用户ID=1、某个API路径一定存在。

新入站需要以下明确输入；已有对象只改任务授权字段：

| 字段 | 值的来源与检查 |
|---|---|
| 协议与端口 | 用户目标 VLESS + RAW/TCP + REALITY；监听端口从已授权方案取得、确认未被其他服务占用 |
| 客户端 | 用面板生成独立 UUID；Vision目标为 `xtls-rprx-vision`，保存后核对生成配置 |
| REALITY目标 | 从该VPS实测候选站TLS1.3及证书名称；SNI在serverNames中，目标host:port与纯SNI分开 |
| X25519 | 面板/该版本Xray受支持生成接口；私钥留服务端，公钥给客户端；密钥配对在内存核对 |
| short ID | 按该版本约束生成/填写并与客户端一致；不输出到公开记录 |
| 客户端映射 | Mihomo `network: tcp` 对应服务端 RAW；tls=true、实际servername、公钥、short-id、flow、client-fingerprint |
| UDP/XUDP | 只有双方支持才设置 `udp: true` 和 `packet-encoding: xudp`，再做实际UDP往返；不能靠此修复TCP超时 |

当前字段参考：[Mihomo VLESS](https://wiki.metacubex.one/config/proxies/vless/)。执行前以目标版本为准。不存在字段或保存响应错误立即停止；不试探性补字段或修改无关全局设置。

GUI操作成功条件：保存反馈成功、重新打开同一入站与目标客户端、生成Xray配置中数量/启用状态/flow与预期一致。API成功条件：对应版本定义的HTTP状态与业务成功字段同时满足，再回读；200但业务错误仍为失败。私密响应不上传。

## S4 监听与网络策略

读取实际监听/PID和主机规则，再从云实例详情核对关联的安全组/独立防火墙/端口映射。只有授权需要的单端口规则可改；协议、源范围、实例绑定和保存/应用后回读都要记录。没有控制台权限就停止该层写入，不能关整组或开放所有端口。

规则保存不证明数据平面放行。用同窗独立探针和目标头部观测验证；细节见 [排障 C](troubleshooting.md)。REALITY未认证回落只验证相应TLS路径，不证明VLESS身份成功。以下命令在目标服务器执行，变量均取S3实际值：

```sh
openssl s_client -connect "127.0.0.1:$NODE_PORT" -servername "$REALITY_SNI" -verify_hostname "$REALITY_SNI" -tls1_3 -verify_return_error </dev/null
```

需先证实本机OpenSSL支持这些参数。退出0且证书校验成功/TLS1.3符合预期才通过回落项；非零停止，不去掉校验。公网路径仍未通过时不归咎客户端密钥。

## S5 配置校验、加载与业务

1. 运行已由当前Xray帮助确认的配置校验命令；语法通过只通过语法项。
2. 按已核实管理器的单目标加载命令或面板保存机制生效。API/GUI及服务工具的期望结果写在卡内；失败停止，不启动另一套历史xray.service抢端口。
3. 回读目标监听PID、生成客户端/flow与配置摘要。再用R3/O6隔离客户端配置校验以及O5真实认证请求；预期出口必须实测，不能把节点地址当固定出口。
4. 用户要求UDP就做对应协议UDP往返；工具未实现则先准备并测试探针，不用TCP冒充。手机v2box只在用户许可设备上导入，实际访问/出口与GUI延迟分开；二维码含凭据，保存在私有位置。
5. 受保护应用长连接未运行就标未执行；请求回404/403不代表登录或推理成功。失败转R2诊断卡，不能自动换实现求成功。

## S6 可选项与交付

BBR、系统更新、面板凭据/2FA、私有管理隧道、证书均需当前任务包含才建独立卡；核心节点交付不依赖把这些全部做完。

- BBR先读available/current；内置无需modprobe。实际可用后专属sysctl文件应用方式见 [命令补充](command-recipes.md)。不可用停止该项，不更换内核。
- 2FA由用户保存密钥并输入动态码，正确码实际登录才算通过；输入框存在仅configured。不自动关闭2FA或打印otpauth。
- 面板私有化先证实既有访问路径、新loopback隧道及IPv6范围，切换需授权；不删除现有HTTPS。
- 账号/端口/base-path由实际fork契约确认，保持原有provider/用户对象；不能猜哈希或设置键。

交付进入G4/G5，报告服务端、客户端和管理面板各自证据、失败与未执行项；无整机重启就不能称持久化实测通过。
