每卡遵守：前提通过 → 执行 → 测试 → 验收 → 提交。失败停止依赖步骤，报告已完成和未执行；不自动回滚或改来源。

### C1 入口与路线（M2）
- 目标：新 AI 能区分只读、部署、整合、排障、应用保护、防泄露、重启。
- 范围：SKILL.md、README、references/runbook.md、references/operations.md、任务卡模板和旧引用矛盾处。
- 前提：M1 审查清单完成；沿用已有授权，不接触生产。
- 步骤：定义输入/路径发现 → 路线门槛 → 精确操作卡 → 证据状态 → 安装说明。
- 停止：出现无法核验的通用安装/API 参数；将具体目标路线标 blocked，不凭空补命令。
- 验收：每条路线有进入/成功/停止/交付；只读、离线、不关软件情景可结束且不越权。

### C2 离线辅助工具（M2）
- 目标：替换易误用示例，形成真实可调用契约。
- 范围：scripts/skillctl.py、SQLite/日志/PF 功能、assets 探针。
- 前提：明确输入均为显式绝对路径；工具不加载 PF、不改代理、不联网。
- 步骤：实现错误码及独占写入 → 自包含安装 → 明确依赖探测 → 隔离资产测试。
- 停止：不明 schema、损坏/缺失输入、权限不足、目的已存在或符号链接；保留部分产物证据。
- 验收：正常与负向测试、原输入哈希不变、输出权限/无覆盖、无凭据回显。

### C3 包装与代码测试（M3）

- 停止：任何失败；记录原因修复后重跑受影响项及完整发布检查，不跳过测试来提交。
- 验收：缺依赖/权限/路径/损坏输入/已有安装/部分安装/探针超时均有实际断言。
